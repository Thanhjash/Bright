# Decision: Layer 1 memory is enough — stop deepening Store B

**Date:** 2026-08-17  
**Status:** LOCKED  
**Authority:** [north-star.md](../NORTH-STAR.md) · live chats `minh-show` / `minh-c3`

## Decision

Do **not** spend the next cook on a richer data layer (FTS5, BKT, Mem0,
chat history, GraphRAG, more skill estimators).

Hermes already adapts like a teacher with a mark book: `observations` +
`mode` (name ≠ point) + `SKILL_CARD`/`PAST` + RAM `BEATS`. That is the
correct shape for 1:1 Pre-A1. More index is not more teaching.

## What “adapt / personalize” means *now*

| Claim | True? |
|---|---|
| Off-script → read keys, teach that thing | Yes (live) |
| Next session reviews named vs only pointed | Yes |
| Off-topic is human, not a new objective | Yes |
| Chat log is student truth | No — NS-5 |
| Personalized learning path / BKT / weekly profile | No — later, after cohort data |

Better adapt at this stage is **better `keys.md` / maps / clips**, not a
new store.

## When Store B may grow again

Only after: Stage TTS of `say`, Bright ASR into `/teacher/turn`, or a
measured miss (library too big for token search; pooled data for BKT).

Camera later only binds `student_id`. It does not invent memory.

## Next cook

Roadmap nấc 3: **pipes** (voice), same 8 tools. Not more SQLite.
